# V1.101: SEGA 로고 뒤 정지 제보 대응

GDEMU/MODE 계열 ODE로 실행한 실기에서 SEGA 로고 뒤 진행되지 않는다는 제보에 대응합니다. **제보된 기기에서 재현하거나 해결을 확인한 상태는 아닙니다.** 소스에서 확인된 초기 캐시 동기화 누락을 수정하고 ODE용 GDI 출력을 추가했습니다.

## 발견한 위험과 변경

V1.1은 ZENFONT.GD를 읽은 다음, 그 파일 뒤에 포함된 한국어 자막·설정 코드를 캐시 영역 P1의 고정 진입점으로 바로 실행했습니다. 실행 중 추가 훅을 설치할 때의 캐시 처리는 있었지만, 새 코드를 **처음 실행하기 전**의 동기화는 없었습니다. SH-4에서 데이터로 읽은 코드와 명령 캐시가 서로 일치하지 않으면 잘못된 명령을 실행할 수 있으므로 실기 정지의 의심 지점으로 판단했습니다.

V1.101은 이미 부팅되어 실행 중인 본체 코드에 56바이트 초기 진입 루틴을 두었습니다. 이 루틴이 원래 게임의 데이터 캐시 writeback 함수를 호출한 뒤, 추가 코드의 비캐시 영역 P2로 이동합니다. P2에서 명령 캐시를 무효화하고 대기 명령을 거쳐 정상 진입점으로 넘어갑니다. 교체된 원래 폰트 초기화 함수는 같은 명령 동작으로 재배치했습니다.

이 순서는 [Renesas SH7750 하드웨어 매뉴얼](https://www.renesas.com/en/document/mah/sh7750-sh7750s-sh7750r-group-users-manual-hardware?r=1055166)의 캐시 구조와 [KallistiOS의 캐시 처리 구현](https://github.com/KallistiOS/KallistiOS/blob/master/kernel/arch/dreamcast/kernel/cache.s)을 참고해 검토했습니다. **증상 원인이 확정됐다는 뜻은 아닙니다.**

| 항목 | V1.101 |
| --- | --- |
| 본체 초기 진입 루틴 | `0x8c03add6`, 56바이트 |
| 기존 데이터 캐시 writeback 함수 | `0x8c0163b6` |
| 처음 실행하는 추가 코드 주소 | `0xac2f0030` (P2) |
| 추가 코드 크기 | 37,588바이트 |
| 추가 코드 BSS 끝 | `0x8c2f9900` |
| 기존 메인 힙 시작 | `0x8c300000` |
| 변경 파일 | `1ST_READ.BIN`, `ZENFONT.GD` 및 폰트 파일 크기 기록 |
| V1.1 대비 변경 섹터 | 21개 |

기존 자막 데이터·가사·영상·음성·판정 C 코드는 이번 수정으로 바꾸지 않았습니다. ROM의 부팅 영역(IP.BIN), ISO 파일 위치, 나머지 ISO 파일 251개는 유지했습니다.

## ODE용 GDI 출력

[GDEMU 제작자 문서](https://gdemu.wordpress.com/details/gdemu-details/)에 맞춰 `disc.gdi`와 짧은 영문 트랙 이름을 사용합니다. [cue2gdi의 변환 구현](https://github.com/99z/cue2gdi/blob/master/src/main.zig)과 원본 CUE의 INDEX를 대조했습니다. 이 적용기는 해시가 고정된 일본판 3트랙 덤프만 처리합니다.

```text
3
1 0 4 2352 track01.bin 0
2 992 0 2352 track02.raw 0
3 45000 4 2352 track03.bin 0
```

Track 1의 842섹터 다음에 원본 Track 2의 150섹터 프리갭이 있어 오디오 시작 LBA는 992입니다. 오디오 파일의 앞 352,800바이트만 제외하며, 오디오 샘플 자체는 바꾸지 않습니다. 고밀도 Track 3 시작 LBA는 45000으로 유지합니다. GDI에서 Track 1·Track 3의 파일 내용은 CUE 출력과 같습니다.

## 확인한 범위

- 원본 바이트 일치 확인, SH-4 조립과 링크, 디스어셈블리 검토.
- 실제 생성된 부팅 명령을 제한된 명령 모델로 실행해 writeback→P2 실행→명령 캐시 무효화→P1 실행 순서, 인자·복귀 주소·스택과 보존 레지스터를 검사.
- 원래 폰트 초기화 함수의 28개 명령을 재배치 전후 비교. PC 상대 리터럴의 실제 값과 두 복귀 경로가 동일함을 확인.
- 자막 테이블 바이트 일치, 힙 경계, 디스크 변경 섹터의 EDC/ECC와 변경 범위 확인.
- 배포 EXE로 원본에서 CUE/GDI를 각각 생성하고 총 8개 결과 파일의 크기·SHA-256을 독립 대조.

**실제 SH-4 캐시 타이밍, ODE 펌웨어와 실기 부팅은 명령 모델로 검증할 수 없습니다.** 새 음성 재생·전체 스테이지·화면 검수는 이번 범위에 포함하지 않았습니다.
