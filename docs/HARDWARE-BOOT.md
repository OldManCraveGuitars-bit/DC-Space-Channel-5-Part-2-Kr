# V1.103: 추가 자막 초기화 시점 변경

**V1.102에서도 SEGA 로고 뒤 정지가 계속된다는 실기 결과를 받았습니다.** V1.103은 부팅 초기에 설치하던 추가 자막 훅 6개를 타이틀 생성 시점으로 옮겼습니다. 로고 단계에서 추가 자막 코드가 음성 핸들을 매 프레임 조회하는 경로를 제거했습니다.

**초기화 순서상 위험을 줄인 수정이며, 실제 Dreamcast/ODE에서 해결됐는지는 아직 확인되지 않았습니다.** 원인 확정이나 실기 부팅 성공으로 안내하지 않습니다.

## 확인한 위험과 수정

V1.102는 `ZENFONT.GD` 로딩 직후 원래 글꼴 초기화와 추가 자막 초기화를 함께 실행했습니다. 이때 프레임 종료와 CRI 음성 시작 함수 등 6개 실행 훅을 설치하므로, 타이틀에 도달하기 전부터 추가 자막 코드가 음성 상태를 조회했습니다. 실기의 초기화 순서·처리 시간 차이에 노출될 수 있는 부분으로 판단했습니다. 이 경로가 제보된 정지의 직접 원인인지는 확정하지 못했습니다.

V1.103의 폰트 로딩 직후에는 설정 상태 초기화와 원래 게임의 글꼴 초기화만 실행합니다. `TITLE.BIN`의 타이틀 생성 함수에 진입할 때 자막 훅을 설치한 뒤, 원래 생성 함수를 그대로 이어서 실행합니다. 옵션 메뉴를 열거나 VMU가 연결되어 있어야 하는 조건은 없습니다. 재호출 때는 기존 초기화 함수의 중복 설치 방지를 유지합니다.

타이틀 함수의 원본 12바이트를 확인한 뒤 분기 코드를 넣고, 대체 어셈블리에서 원래 명령과 인수를 복원합니다. 고정 진입 주소는 `0x8c2f0050`입니다. 원래 폰트 함수의 28개 명령도 기존처럼 보존합니다.

파트1 한글판이 실기에서 동작한다는 사용자 제보도 반영했습니다. 소스 비교상 파트1은 메인 실행 파일의 여유 공간에 추가 코드를 내장하고, 파트2는 폰트 파일 로딩 경로로 읽어 들이므로 초기화 방식이 다릅니다. 파트1의 주소나 코드를 파트2에 복사하지 않았습니다. 기기·펌웨어·실행 조건이 모두 동일한지는 독립 확인하지 않았습니다.

## 보존한 내용

- 기존 자막·가사·음성 연결·타이밍·글꼴 데이터.
- 판정 설정 1~6단계, 기본 1, VMU 파일 형식과 저장 코드.
- V1.101의 첫 진입 캐시 처리, V1.102의 RAM ASCII 글꼴·BSS 0 초기화·훅 설치 중 인터럽트 보호.
- 원본 IP.BIN, 모든 ISO 파일 위치와 다른 파일 250개.

## 이번 확인 범위

- 기존 객체 파일을 그대로 재사용하고 SH-4 어셈블리·링크·디스어셈블리를 확인했습니다.
- 변경한 두 진입 경로의 실제 명령을 제한 모델에서 실행하여 호출 순서, PR/SP와 인수 보존을 확인했습니다.
- Flycast의 새 부팅에서 타이틀 전에는 6개 원본 훅이 유지되고, 타이틀 생성 뒤에만 6개가 설치되는지 RAM으로 확인했습니다. 입력은 START만 사용했고 게스트 RAM 쓰기·저장 상태 복원은 하지 않았습니다.
- 변경 23개 섹터의 EDC/ECC와 범위를 확인하고, 배포 EXE로 원본에서 CUE/GDI를 각각 생성해 8개 결과 파일의 크기·SHA-256을 대조했습니다.

위 결과는 실기 호환성 보증이 아닙니다. 새 음성 재생·전체 플레이·자막 화면 검수는 반복하지 않았습니다.
