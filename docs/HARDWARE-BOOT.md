# V1.104: GD-ROM 끝부분의 파일 배치 수정

**V1.103도 실기에서 멈춘다는 제보를 받아 디스크 배치를 수정했습니다.** 타이틀 파일과 의상실 이미지가 원본의 마지막 150섹터 여백에 배치되어 있었습니다. 두 파일을 정상 데이터 영역으로 옮기고, 끝부분은 원본과 바이트 단위로 동일하게 복원했습니다.

**실제 Dreamcast/ODE에서 해결됐는지는 아직 미확인입니다.** 이번에는 실 BIOS 파일을 사용하는 에뮬레이터에서 타이틀 파일 적재와 초기화 진입을 확인했습니다. 실기 성공으로 안내하지 않습니다.

## 발견한 배치 문제

일본판 원본 Track 3의 마지막 150섹터(LBA 549000~549149)는 데이터가 없는 끝부분입니다. 이전 한글판은 이 영역을 확장 파일용 여유 공간으로 취급해 `TITLE.BIN`과 `COSROOM.PVM`을 넣었습니다. 실행 코드를 조정한 V1.101~V1.103에서도 이 배치는 그대로였습니다.

타이틀 생성에 필요한 파일이 이 끝부분에 있으면, 끝부분을 일반 파일 영역과 다르게 취급하는 읽기 경로에서 문제가 될 수 있습니다. 이번 수정은 확인된 원본 배치 이탈을 제거합니다. 이것이 모든 제보 기기에서 정지의 직접 원인이었는지는 실기 결과를 받아야 확정할 수 있습니다.

| 파일 | V1.103 위치(LBA) | V1.104 위치(LBA) | 크기 |
| --- | ---: | ---: | ---: |
| TITLE.BIN | 549000 | 45856 | 96,044바이트 |
| COSROOM.PVM | 549048 | 45920 | 147,120바이트 |

두 목적지는 원본과 V1.103에서 모두 비어 있고 다른 파일과 겹치지 않는 영역임을 확인했습니다. ISO 디렉터리의 위치 값만 갱신했으며 두 파일의 내용·크기는 그대로입니다. 마지막 150섹터는 섹터 헤더와 오류 정정 데이터를 포함해 원본과 동일하게 복원했습니다. 이후 빌드에서도 이 끝부분에 새 파일을 배치하지 않도록 생성 도구의 할당 상한을 수정했습니다.

## 보존한 내용

- ISO 파일 253개의 내용 전부 동일. `1ST_READ.BIN`, `ZENFONT.GD`, TITLE 실행 코드도 V1.103과 동일합니다.
- 원본 부팅 파일의 위치 LBA 548365, 크기 1,299,396바이트, 원본 IP.BIN과 트랙 길이 유지.
- 모든 AFS의 위치와 내용, 자막·가사·음성 연결·글꼴·타이밍 유지.
- 판정 설정 1~6단계와 VMU 자동 저장 코드 유지.
- V1.103 대비 변경 240섹터. 그 외 원시 섹터는 동일합니다.

## 확인 범위와 한계

실 BIOS 파일과 `UseReios=no`를 쓰는 별도 Flycast 환경에서 GDI를 새로 부팅했습니다. 재배치한 TITLE 파일의 적재, 타이틀 생성 시 추가 훅 6개 설치, 설정 읽기 상태를 메모리로 확인했습니다. 캡션 관찰용 외부 훅, 게스트 RAM 쓰기, 저장 상태 복원은 사용하지 않았습니다. 소리를 끄고 START 입력만 사용했으며 새 음성·자막 화면 검수를 반복하지 않았습니다.

배포 적용기로 원본에서 CUE/GDI를 각각 생성하고 8개 결과 파일의 크기와 SHA-256을 대조했습니다. 실기 ODE 확인을 대체하는 결과는 아닙니다.

조사 중 메인 실행 파일을 앞쪽 빈 공간으로 옮기는 안도 시험했지만 BIOS 부팅 제약과 맞지 않아 제외했습니다. **최종 배포본에는 그 실행 파일 확장·이동이나 새 초기화 코드가 없습니다.** 부팅 실행 파일의 위치 제약은 [GDIBuilder 개발자 설명](https://projects.sappharad.com/tools/gdibuilder.html)도 참고했습니다. 최종 수정에서는 원본 위치를 유지합니다.
