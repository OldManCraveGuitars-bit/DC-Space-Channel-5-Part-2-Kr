# V1.102: SEGA 로고 뒤 정지 재제보 대응

**V1.101에서도 실기에서 동일하게 진행되지 않는다는 결과를 받았습니다.** V1.102는 아래 위험을 제거한 후속 수정입니다. 제보된 Dreamcast/ODE에서 직접 재현하거나 V1.102 부팅 성공을 확인한 상태는 아닙니다.

## 1. 추가 자막의 BIOS 글꼴 접근 제거

기존 추가 자막 코드는 초기화에서 BIOS 글꼴 주소를 얻고, 영문·숫자·기호를 그릴 때 BIOS ROM을 직접 읽었습니다. 이 코드에 G1 버스 잠금이 없었습니다. [KallistiOS 시스템 호출 문서](https://github.com/KallistiOS/KallistiOS/blob/master/kernel/arch/dreamcast/include/dc/syscalls.h)는 BIOS 글꼴 데이터 접근 전에 잠금이 필요하며 G1 DMA 중에는 해당 글꼴을 읽을 수 없다고 명시합니다. 디스크 읽기와 겹칠 수 있는 실기 호환성 위험으로 판단했습니다.

V1.102에서는 추가 자막의 BIOS 글꼴 호출과 ROM 직접 읽기를 제거했습니다. 기존에 배포하던 영덕 블루로드체로 ASCII 96칸을 생성해 `ZENFONT.GD`의 남은 공간에 넣고, 게임 RAM에서 읽습니다. BIOS 파일이나 BIOS 글꼴 데이터는 배포물에 넣지 않았습니다.

한글 자막 문장·타이밍·기존 한글 글꼴·행 배치는 그대로입니다. **추가 자막의 영문·숫자·기호 모양은 12×24 영덕 블루로드체 기반으로 바뀝니다.** 원래 게임 자체의 BIOS 사용 코드는 수정하지 않습니다.

## 2. 추가 코드의 전역 변수 초기값 명시

V1.101의 추가 코드 파일에는 실행 코드와 초기화된 데이터만 들어 있었고, 추가 BSS 구간은 파일 뒤의 RAM에 놓였습니다. 게임 원래 시작 코드의 초기화 범위 밖이므로 실제 기기의 남은 RAM 값에 의존할 여지가 있었습니다.

V1.102는 추가 BSS **1,580바이트**를 명시적인 0 데이터로 폰트 파일 끝에 포함합니다. 기존 폰트 로더가 파일을 읽으면서 해당 RAM도 초기화합니다. 메인 힙 시작 주소는 유지합니다.

## 3. 실행 코드 설치 구간 보호

기존에는 추가 훅의 명령을 쓴 다음 캐시를 동기화하는 구간에만 인터럽트 차단이 있었습니다. V1.102는 원본 바이트 확인을 마친 후, 6개 훅의 명령 쓰기부터 캐시 동기화 완료까지 인터럽트를 차단합니다. 완료 후 저장한 상태 레지스터를 복원합니다. 원본 코드가 예상과 다르면 아무 훅도 쓰지 않고 반환합니다.

V1.101의 첫 진입 캐시 동기화는 유지합니다. 이번에 실제 디스크에서 바뀐 것은 `1ST_READ.BIN`의 부팅 코드 길이 리터럴과 `ZENFONT.GD`, ISO의 폰트 크기 기록입니다.

| 항목 | V1.102 |
| --- | --- |
| 추가 실행 코드 | 37,496바이트 |
| RAM ASCII 글꼴 | `0x8c2eec80`, 3,456바이트, 12×24 × 96칸 |
| 명시적 BSS 0 데이터 | 1,580바이트 |
| 폰트 파일 전체 크기 | 235,684바이트 |
| 추가 코드/BSS 끝 | `0x8c2f98a4` |
| 메인 힙 시작 | `0x8c300000` |
| V1.101 대비 변경 섹터 | 25개 |
| 부팅 영역·ISO 파일 위치 | 유지 |
| 나머지 ISO 파일 | 251개 유지 |

## 확인한 것과 남은 범위

- 원본 바이트와 V1.101 기준 해시, SH-4 조립·링크·디스어셈블리 확인.
- 실제 생성된 초기화 명령을 제한된 명령 모델에서 실행: 첫 초기화, 이미 설치된 상태의 재호출, 예상과 다른 원본 바이트의 세 경우.
- 명령 36개 반워드 쓰기 모두에서 인터럽트 차단, 캐시 동기화 호출 6회, 레지스터·복귀 경로 복원 확인.
- 캐시 부트스트랩 모델, 자막 테이블·연결 데이터 일치, 글꼴/BSS/힙 경계 검사.
- 변경 25섹터의 EDC/ECC와 범위 확인. IP.BIN, 파일 위치와 다른 파일 보존 확인.
- 배포 EXE로 원본에서 CUE/GDI 각각 생성 후 결과 8개 파일의 크기·SHA-256 대조.

**이는 실기 부팅 성공 검증이 아닙니다.** BIOS/G1 접근 위험과 초기화 문제를 제거했지만 제보 증상의 원인은 아직 확정하지 못했습니다. 새 음성 재생·전체 플레이·화면 검수는 반복하지 않았습니다.

GDEMU/MODE용 GDI 출력은 V1.101과 같습니다. `disc.gdi`와 `track01.bin`, `track02.raw`, `track03.bin`을 함께 사용합니다. Track 2는 150섹터 프리갭만 제외하고, Track 3 시작은 LBA 45000입니다.
